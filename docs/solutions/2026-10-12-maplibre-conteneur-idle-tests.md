# MapLibre dans React + Tailwind : placer le conteneur par une boîte autour, demander une image après l'ajout des couches, et ne pas couper les tuiles dans les tests
Étiquettes : build, tests · Tranche : loyer-mer · Source : /build tâche 2 du 2026-10-12

**Problème** — Faire attendre aux tests Playwright que la carte soit peinte (attribut posé sur l'événement `idle`), avec la fixture et un fond local.
**Symptômes** — (1) Le canvas fait 1440 × 300 px : la feuille de style de MapLibre (`.maplibregl-map { position: relative }`, hors couche CSS) l'emporte sur la classe Tailwind `absolute inset-0` (dans une couche). (2) `inset-0` ne produisait d'ailleurs aucun style : le thème Tailwind est vidé, et zéro n'y était pas défini. (3) `idle` n'arrive jamais : la dernière image est dessinée avant que les tuiles d'estompage refusées par le test finissent en erreur, et une erreur de tuile ne redemande pas d'image.
**Ce qui n'a pas marché** — Corriger la taille seule ; `map.triggerRepaint()` juste après l'ajout des couches ; répondre 404 au lieu de couper (même effet).
**Ce qui a marché** — Conteneur MapLibre en `h-full w-full` dans une boîte `absolute inset-0` ; `--spacing-0: 0px` dans le thème généré ; dans les tests, servir une image PNG transparente pour l'estompage (la coupure totale reste réservée au test de panne). Diagnostic décisif : journaliser la suite des événements de la carte (`load`, `render`, `sourcedata`, `idle`, `error`) avec `map.loaded()`.
**Prévention** — Toute nouvelle classe utilitaire « valeur » (`inset-*`, `m-*`…) se vérifie dans le CSS construit. Un test de carte double les services extérieurs par des réponses valides, pas par des refus, sauf quand il teste justement la panne. Ne pas lier un état de l'interface à `idle` (seulement les tests).
